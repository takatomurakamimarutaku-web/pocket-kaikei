# 証憑の撮影・添付（v0.32.0）

領収書・請求書などの証憑を仕訳に添付し、日付・金額・取引先で検索できるようにした。
電子取引のデータ（メールで受け取った PDF の請求書など）を、受け取ったまま保存する場所としても使える。

## 位置づけ（税法の確認結果）

確認した資料（すべて国税庁）

- 「電子取引データの保存方法をご確認ください」 https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/tokusetsu/pdf/0023011-012.pdf
- 電子帳簿保存法一問一答【電子取引関係】 https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/pdf/0024005-113_r603.pdf
- 電子帳簿保存法一問一答【スキャナ保存関係】 https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/pdf/0024005-113_r602.pdf

### 電子取引のデータ（電子帳簿保存法第7条）

| 要件 | 根拠 | Pocket会計 | 利用者がすること |
| --- | --- | --- | --- |
| 真実性（改ざんの防止） | 規則4①一〜四のいずれか | ファイルをそのまま保存し、保存日時と SHA-256 のハッシュ値を記録。中身は変更不可（情報の項目だけ直せる）。削除はできるので「訂正削除ができないシステム」（三号）とは言わない | 事務処理規程（四号）を備え付けて守る。ひな形を「電子帳簿保存」の画面に用意 |
| 見読可能装置 | 規則2②二 | 画面に表示・保存・共有 | 求められたときに表示できる端末を用意 |
| 検索機能 | 規則2⑥五（一問一答 問43） | 証憑の一覧で取引年月日・取引金額の範囲、取引先を組み合わせて検索。索引簿の CSV | 添付するときに日付・金額・取引先を入れる（空欄は仕訳から補う） |
| ダウンロードの求め | 規則4① | バックアップ（証憑を含める）と証憑ごとの保存 | 基準期間の売上高が5,000万円以下なら、ダウンロードの求めに応じられれば検索機能は不要 |

- 「相当の理由」がある場合の猶予措置（ダウンロードの求めと出力書面の提示に応じられれば保存だけでよい）は、画面では扱わない
- 事務処理規程のひな形は、国税庁のサンプル（法人の例・個人事業者の例）の項目（目的・管理責任者・対象・訂正削除の原則禁止・やむを得ない場合の手続・保存期間）を参考に、Pocket会計で保存する前提で書き直した。個人は「記録」、法人は「申請書と管理責任者の承認」
  - 国税庁のサンプルの Word ファイルは取得できなかったため、文言は写していない（一問一答 問29 の例の構成を参考にした）

### 紙の証憑の撮影（スキャナ保存はうたわない）

スキャナ保存の要件（200dpi 以上・赤緑青各256階調以上、タイムスタンプ又は訂正削除の記録、入力期間、帳簿との相互関連性、
14インチ以上のカラーディスプレイ等の見読可能装置、検索機能など）のうち、タイムスタンプ・表示装置・入力期間の管理などは
アプリだけでは満たせないため、**紙の原本も保存する前提**とし、画面にもそう書いた。

- 撮影した画像は長辺2,400ピクセルまで縮めて JPEG（品質0.85）で保存する。A4 を 200dpi で読むと 2338×1654（約387万画素）なので、
  これを下回らない大きさにしておく（将来スキャナ保存に対応するときに作り直さなくてよいように）
- 2,400ピクセル以下の写真は縮めずにそのまま保存する

## データ

- IndexedDB に2つのストアを追加（`DB_VERSION` 6）
  - `attachments`：情報。`{ id, journalId, kind: 'paper'|'electronic', name, type, size, sha256, date, amount, partner, memo, thumb, createdAt, updatedAt }`、`journalId` の索引
  - `attachmentData`：中身。`{ id（attachments と同じ）, data: ArrayBuffer, createdAt, updatedAt }`
- `thumb` は一覧用の縮小画像（長辺240ピクセルの JPEG の data URL）。PDF などは持たない
- 添付できる種類：JPEG・PNG・WebP・GIF・HEIC・PDF・XML・CSV・テキスト。1ファイル10MBまで
  - 画面で表示するのは JPEG・PNG・WebP・GIF だけ。PDF などは共有・保存で開く（HTML や SVG はスクリプトが動くおそれがあるため受け付けない）

## Repository

- `saveAttachment(meta, data)`：ハッシュ値と大きさは中身から計算して記録する（渡された値は使わない）。同じ id で2回保存すると誤り（中身は変えられない）。
  仕訳を指定するときは、その仕訳があること・締めた期間でないこと
- `updateAttachment(id, patch)`：種類・取引年月日・金額・取引先・メモだけ直せる
- `deleteAttachment(id)`：情報と中身を消して tombstone を残す
- 仕訳を削除しても証憑は消さない（電子取引のデータは保存期間中残す必要があるため）。証憑の一覧で「仕訳が削除された証憑」を探せる

## 画面

- 仕訳の入力（振替伝票）とかんたん入力に「証憑」の欄。「撮影する」（カメラ）と「ファイルを選ぶ」
  - 追加するときに種類・取引年月日・金額・取引先・メモを確かめる。初期値は仕訳の日付・借方合計・取引先（現金預金以外の補助科目、なければ摘要）
  - 新しい仕訳では「未保存」として持ち、仕訳を登録したときに保存する（空欄の項目は登録した仕訳で補う）。保存済みの仕訳ではすぐ保存する
  - 締めた期間の仕訳は表示だけ
- 仕訳帳：証憑のある仕訳にクリップの印
- 証憑の一覧（`#/attachments`、「その他」「入力」のメニュー）：すべての会計期間の証憑を、取引年月日・金額の範囲、取引先（取引先・メモ・ファイル名）、種類、仕訳のない証憑で絞り込む。
  索引簿の CSV（保存用のファイル名は国税庁の例「20221031_㈱国税商事_110000.pdf」と同じ並び）
- 電子帳簿保存：電子取引のデータの要件とアプリの対応、事務処理規程のひな形（書き出し・コピー）

## バックアップ

- `BACKUP_VERSION` 6。証憑の情報と中身（base64）を含める。v5 からは証憑を空で変換
- 書き出しで「証憑の中身も含める」を外すと、証憑を含めず `attachmentsOmitted: true` を付ける。これを復元すると、その端末の証憑は消さずに残す
- 復元の前に、中身の大きさと SHA-256 のハッシュ値が記録と一致するか確かめる。一致しなければ何も変更しない

## 未確認・未対応

- 実機（iPhone の Safari・ホーム画面のアプリ）でのカメラ起動・HEIC の扱い・大きなバックアップの書き出しは未確認（Chromium の自動テストで確認）
- スキャナ保存の要件への対応（タイムスタンプなど）は未対応。紙の原本の保存が前提
- 証憑の訂正・削除の履歴（電子取引の真実性の三号）は未対応。事務処理規程（四号）で対応する前提
- 仕訳から外した証憑を別の仕訳につなぎ直す機能は未対応

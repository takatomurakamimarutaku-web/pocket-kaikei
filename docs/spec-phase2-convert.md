# ほかの会計ソフトへ移る「移行パック」（v0.60.0）

Pocket会計から、ほかの会計ソフトへ帳簿を移すためのファイル一式を ZIP で書き出す。
画面は「その他 → 会計ソフトとの受け渡し」（`#/transfer`）の「ほかの会計ソフトへ移る（移行パック）」。
ファイルは端末の中で作るだけで、外部へ送信しない（方針どおり）。

検討の経緯（実現可能性・対象ソフトの選定・ソフトごとの可否）は検討ドキュメントにまとめた（2026-10-29）。
弥生インポート形式は弥生の全製品とマネーフォワードが読めるため、第1弾はこれを軸にした。freee は形式が別なので第2弾。

## 移行先と制限（`js/convert.js` の `CONVERT_TARGETS`）

| 移行先 | 1ファイルの上限 | 1仕訳の行数 | その他 | 期首残高 |
| --- | --- | --- | --- | --- |
| 弥生会計（デスクトップ）・やよいの青色申告 | なし | なし | 科目そのものは取り込めない（手順書で事前作成を案内） | 弥生の期首残高データ |
| 弥生会計 Next | 5,000行 | 100行 | 科目・補助・部門は取り込み時に作成 | 弥生の期首残高データ |
| 弥生会計 オンライン・やよいの青色申告 オンライン | 1,000行・1.0MB | 20行 | 項目内の「,」は全角に置き換え。製造原価の科目は不可 | 弥生の期首残高データ |
| マネーフォワード クラウド会計・確定申告 | なし | なし | 他社ソフトデータの移行（弥生会計）で読む | 手入力用の一覧 |

科目名などの長さは、弥生の「24桁」を Shift_JIS のバイト数（全角12文字）と解釈して注意を出す（推測。切り捨てられるだけで取り込みは止まらない）。

## ZIP の中身（`buildConvertPack()`）

| ファイル | 形式 | 用途 |
| --- | --- | --- |
| 00_移行の手順.txt | UTF-8（BOM） | 移行先の画面の名前で、設定→期首残高→仕訳→照合の手順 |
| 01_期首残高_弥生インポート形式.csv | Shift_JIS | 期首日・勘定科目名・貸借区分・補助科目名・部門・前期繰越残高の6列。科目・補助ごとに合計、0円は出さない |
| 01_期首残高の一覧.csv（MF のみ） | UTF-8（BOM） | 手で入力するための一覧 |
| 02_仕訳_弥生インポート形式.csv（`_1of3` など） | Shift_JIS | 既存の `yayoiRows()`。上限で分けるときも伝票（2110〜2101）の途中では切らない |
| 03_勘定科目と補助科目の一覧.csv | UTF-8（BOM） | 移行先で科目を作る・対応させるときの参考 |
| 04_固定資産台帳.csv（資産があるとき） | UTF-8（BOM） | 移行先で手入力するため（固定資産台帳の画面の CSV と同じ） |
| 05_残高試算表_期末（照合用）.csv | UTF-8（BOM） | 取り込み後の照合用 |

- 期首残高の貸借区分は科目の残高側、金額はその向きの金額（マイナスの残高はマイナスのまま。符号の扱いは資料に記載がなく推測）
- 事業主貸・事業主借・元入金は弥生の期首残高データに入れられない（資料に明記）ので出さず、手順書に書く
- 書き出す前に `convertChecks()` で確かめる。取り込めないもの（行数超過の仕訳・オンライン版の製造原価の科目）があれば書き出さない。
  長い名前・MF の経過措置の税区分は注意として出す。Shift_JIS にない文字は「?」にして知らせる

## 確認したこと

- テスト（`test/convert.test.js` 7件）：期首残高の行（補助ごと・元入金を除く・0円を除く）、伝票を切らないファイル分割（行数・バイト数）、

  書き出した仕訳を Pocket会計の取り込みで読み直せる）、MF のパック（期首残高の一覧・固定資産台帳）、科目の一覧

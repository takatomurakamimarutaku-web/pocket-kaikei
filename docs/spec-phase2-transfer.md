# 会計ソフトとの受け渡し（v0.33.0）

ほかの会計ソフトから Pocket会計に移るとき、また税理士さんに帳簿を渡すときのために、仕訳の CSV の取り込みと、
弥生会計のインポート形式での書き出しを作った。画面は「その他 → 会計ソフトとの受け渡し」（`#/transfer`）。
「入力」の画面からも「ほかの会計ソフトの仕訳の取り込み」で開ける。

ファイルは端末の中で読み書きするだけで、外部へ送信しない（方針どおり）。

## 確認した資料

- 弥生会計 サポート情報「仕訳データの項目と記述形式（他製品から仕訳データをインポートする場合など）」
  https://support.yayoi-kk.co.jp/subcontents.html?page_id=18545
  - 25 列、見出しなし。識別フラグ 2000（伝票以外の仕訳データ）・2111（1行の伝票）・2110（複数行の1行目）・2100（中間行）・2101（最終行）
  - タイプ：0 仕訳データ・1 出金伝票・2 入金伝票・3 振替伝票
  - 決算：空欄・「中決」・「本決」。調整：「yes」・「no」
  - 税金額は税抜経理のときだけ必要
- 弥生会計 サポート情報「消費税の税区分と税計算区分の一覧」 https://support.yayoi-kk.co.jp/subcontents.html?page_id=18111
  - 税区分の書き方：「課税売上込10%」「課対仕入込軽減8%」のように、税込は「込」、軽減税率は「軽減8%」
  - インボイスのない仕入の経過措置は末尾に「区分80%」「区分50%」、控除できないものは「区分控不」
- freee ヘルプセンター「仕訳帳をCSV形式・PDF形式で出力する」 https://support.freee.co.jp/hc/ja/articles/204615564
  - 出力項目：No.・取引日・借方勘定科目・借方補助科目・借方金額・借方税区分…・取引先・摘要・決算整理仕訳 など
- インボイスのない仕入の経過措置の割合は `js/tax-return.js` の `transitionalRate()`（国税庁の案内）を使う

アプリのソースには国税庁・e-Tax 以外の URL を書かない決まり（`scripts/check-pwa.js`）なので、
弥生・freee の出典の URL はこの文書にだけ載せ、コードのコメントにはページ名を書いた。

## 取り込み（`js/journal-import.js`、純粋関数）

### 読める形式

| 形式 | 判定 | まとめ方 |
| --- | --- | --- |
| 弥生会計のインポート形式 | 1列目が 2000・2111・2110・2100・2101 で、20列以上 | 2110〜2101 を1つの仕訳にする。「本決」「中決」は決算整理仕訳 |
| 見出しのある CSV（freee・マネーフォワードなど） | 先頭5行のどれかに「取引日（日付）」「借方勘定科目」「貸方勘定科目」「金額」の見出し | 続く行で番号（No.・取引No・伝票番号など）と日付が同じものを1つの仕訳にする。番号の列がなければ1行1仕訳 |

- 文字コードは Shift_JIS と UTF-8 を自動で判定する（銀行明細の取り込みと同じ `decodeBytes()`）。10MB まで
- 日付は「2026/11/02」「2026-11-02」「R8.11.2」などを読む（`parseDate()`）
- 金額は「33,000」「¥33,000」なども整数の円にする。小数は誤り。マイナスの金額は反対側の明細にする。0円の明細は飛ばす
- 取引先の列があれば摘要の先頭に付ける（摘要にすでに入っていれば付けない）
- 誤りには CSV の行番号を付ける

### 科目の照らし合わせ（`suggestAccounts()`）

1. 前回この画面で選んだ対応（`meta.journalImport.accounts`）
2. 同じ名前（全角半角・空白・「・」の違い、「ウエ／ウェ」、末尾の「等」を無視）
3. 表記の違いの組（売上高＝売上、仕入高＝仕入・商品仕入高、期首商品棚卸高＝期首棚卸高 など）

合わない科目は空欄にし、画面で選んでもらう（選ぶまで、その科目を使う仕訳は登録できない）。
選んだ対応は登録したときに保存し、次回の取り込みで使う。

### 税区分の照らし合わせ（`suggestTax()`）

名前の言葉で判定する。弥生（課税売上込10%・課対仕入込軽減8%・課対仕入込10%区分80%）、
freee（課対仕入10%・課対仕入8%(軽)・課対仕入(控80)10%）、マネーフォワード（課税仕入 10%・共-課仕 10%）の表記を想定した。

| 言葉 | Pocket会計の税区分 |
| --- | --- |
| 対象外・不課税・対外 | 対象外 |
| 課税売上 + 10% ／ 軽減 | 課税売上10%／8%（軽減）。「返」「値引」は売上の返還、「倒」は貸倒れ、「回」は貸倒れの回収 |
| 課対・共対・非対 + 仕入 | 課税仕入（課税売上対応・共通対応・非課税売上対応）。「区分」「控80」などは「インボイスなし」 |
| 輸出・免税売上 | 輸出売上（免税）。「返」は輸出売上の返還 |
| 非課売上・非課仕入・有価譲渡 | 非課税売上・非課税仕入・有価証券の譲渡 |
| 輸税・地消貨割 | 輸入の消費税（国税）・地方消費税の貨物割 |

次のものは「対象外」にして、画面に理由を出す（利用者が直せる）。

- 旧税率（8%・5%など）の税区分、税率がわからないもの、判定できないもの
- 控除できない仕入（「控不」）、輸入の本体（「輸本」）、輸出・非課税売上の貸倒れ
- 「非資輸」（非課税資産の輸出）は輸出売上（免税）にし、確かめてもらう

税区分が空欄の明細は、対応させた科目の既定の税区分にする。

### 登録（`Repository.importJournals()`）

- 選んだ仕訳と、その仕訳で使う新しい補助科目を、1つのトランザクションで保存する。1件でも不正なら何も保存しない
- 同じ科目に同じ名前の補助科目があればそれを使う
- 仕訳は `putJournal()` で1件ずつ検証する（貸借一致・会計期間・締めた期間）。誤りは「3件目（2026-11-02）：…」の形
- 今の会計期間の外の日付の仕訳は登録しない（画面で「会計期間外」と表示）
- 日付・科目・補助科目・金額が同じ仕訳がすでにあれば「登録済みかも」と表示し、初めは選ばない
- 期首残高は取り込まない（期首残高の画面で入力する）
- 締めた会計期間では取り込みできない（書き出しはできる）

## 書き出し（`js/yayoi.js`、純粋関数）

- 今の会計期間の仕訳を、弥生会計のインポート形式（見出しなし25列）にする
- 借方・貸方が1行ずつの仕訳は識別フラグ 2000（タイプ 0）、複合仕訳は振替伝票（2110〜2100〜2101、タイプ 3）
- 期末日の決算整理仕訳は「本決」
- 税区分は税込（Pocket会計は税込経理）。インボイスのない仕入は取引日の経過措置の割合を付ける（2026/9/30 までは「区分80%」、
  2026/10/1 からは「区分70%」）。税金額の列は税込金額から割り戻した額
- 文字コードは Shift_JIS（既定）か UTF-8（BOM 付き）
  - Shift_JIS への変換は `js/sjis.js`。変換表は持たず、ブラウザの `TextDecoder('shift_jis')` から逆引きの表を作る
  - 「〜」「−」など Mac・iPhone で入りやすい文字は Shift_JIS の似た文字にする。表せない文字は「?」にして画面で知らせる

## 確認したこと

- テスト（`test/transfer.test.js` 11件）：Shift_JIS の変換、弥生の税区分名、書き出しの行、形式の判定、弥生・見出しありの読み込み、
  科目・税区分の照らし合わせ、書き出したものを読み込むと同じ仕訳になること（往復）、登録の一括保存（1件でも不正なら何もしない）
- 画面（Playwright、`shots/transfer/`）
  - 個人のサンプル（142件）を弥生形式（Shift_JIS）で書き出し、新しい個人の帳簿に取り込むと 142件が登録され、
    科目・補助科目・税区分・貸借ごとの合計が書き出し元と一致する
  - freee の形の CSV：合わない科目（研修費）を選ぶまで登録できない、旧税率の注意、会計期間外の仕訳を除く、
    2回目は前回の対応を使い、同じ仕訳に「登録済みかも」が付く、形式のわからないファイルは誤り表示

# 売掛金・買掛金の管理（v0.34.0）

取引先ごとに、売掛金・買掛金の残高、入金（支払）予定日、消込、滞留を見られるようにした。
画面は「帳票 → 売掛金・買掛金」（`#/receivables`）。取引先を開くと詳細（`#/receivables/party`）。

税法の判断は含まない（帳簿の管理機能）。

## 考え方

| 項目 | 決めたこと | 理由 |
| --- | --- | --- |
| 取引先 | 売掛金・買掛金の補助科目 | 内訳書・元帳と同じ単位にでき、新しいデータを持たずに済む。補助科目を使わない分は「（補助科目なし）」にまとめる |
| 対象の科目 | 役割（`hint`）が `receivable`（売掛金）・`payable`（買掛金）の科目 | 科目名ではなく役割で判定する決まり |
| 消込 | 入金（支払）は古い発生から順に消し込む（先入先出） | 仕訳に「どの請求の入金か」を持たせなくても、多くの取引先では実態に合う。手で組み合わせる消込は持たない |
| 過入金・過払い | 消し込む発生がない入金は「過入金」として持ち越し、次の発生に充てる | 残高がマイナスになる取引先も扱える |
| 前期からの繰越 | 期首残高（正の額）を「期首の前日」の発生として数える | 前期の明細は今の会計期間にないため。経過日数は実際より短く出ることがある |
| 予定日 | 補助科目の支払条件（締め日・何か月後・支払日）から計算する | 「末日締め 翌月末日払い」のように取引先ごとに決まっていることが多い |
| 滞留 | 発生日からの経過日数で年齢表に分け、91日以上を「滞留」とする | 財務DDなどで使う年齢表（30・60・90・180日）に合わせた |
| 基準日 | 画面で選べる（初めは今日。会計期間の外なら期首・期末） | 月末・期末の残高を確かめるため |

### 予定日の計算（`dueDate()`）

- 締め日（31＝末日。その月にない日は月末）までの発生はその月の締め、過ぎたら翌月の締め
- 締めた月の「何か月後」（0＝当月〜3か月後）の支払日（31＝末日。その月にない日は月末）
- 当月払いのときは、支払日を締め日より前にできない（保存しない）

例（末日締め 翌月末日払い）：1/5 → 2/28、1/31 → 2/28、2/28 → 3/31。
例（20日締め 翌月10日払い）：1/20 → 2/10、1/21 → 3/10。

## 画面

- 一覧：売掛金／買掛金の切り替え、基準日
  - 残高・期日超過・滞留（91日以上）・次の予定の4つの数字
  - 年齢表（30日以内〜181日以上）と CSV の書き出し
  - 取引先ごとの残高（支払条件・次の予定日・期日超過・滞留・過入金の印）。残高のない取引先は折りたたむ
  - 予定の一覧（期日を過ぎたもの、予定日ごとの合計）
- 取引先の詳細
  - 期首残高・発生・減少・残高
  - 支払条件の設定（補助科目に保存）
  - 残っている発生（予定日・期日超過の日数・経過日数）
  - 入金の履歴（仕訳へのリンク）
  - 「入金（支払）を記録する」：かんたん入力（売掛金の入金・買掛金の支払）を開き、科目・補助科目・いちばん古い残りの金額・摘要を入れておく
  - 総勘定元帳へのリンク
- ホームの「やること」：支払条件を設定した取引先で予定日を過ぎた残りがあれば「入金予定日を過ぎた売掛金を確かめる」などを出す

## データ

- 補助科目に `paymentTerms: { closingDay, months, payDay } | null` を足した（なくてもよい項目）
  - 保存口は `Repository.saveSubAccount()`。`validatePaymentTerms()` で検証し、誤りは保存しない
  - バックアップの読み込みでも同じ検証をする
  - 新しいストア・索引は作らないため `DB_VERSION` は変えない。項目を足しただけで、古いバックアップはそのまま読めるため `BACKUP_VERSION` も変えない（古い版のアプリは知らない項目を無視する）
- サンプルの取引先に支払条件を入れた（A社：末日締め 翌月25日払い、ほかは末日締め 翌月末日払い）

## 確認したこと

- テスト（`test/receivables.test.js` 12件）
  - 予定日（月末・年またぎ・当月払い・2月）、支払条件の検証と表示、年齢表の区分
  - 先入先出の消込、過入金の持ち越し、補助科目なし、基準日、買掛金、前期からの繰越
  - 予定の一覧、年齢表の CSV
  - サンプル（個人・法人）：取引先ごとの残高の合計が試算表の残高と同じ、残りの合計−過入金＝残高
  - 支払条件の保存（誤りは保存しない）とバックアップでの検証
- 画面（Playwright、`shots/receivables/`、ライト／ダーク）
  - 個人のサンプル：ホームに A社の期日超過の「やること」→ 一覧 → A社の詳細（期日超過4日）
  - 支払条件を変えると期日超過が消える。当月払いで支払日が締め日より前は保存できない
  - 「入金を記録する」で金額 330,000・摘要「A社 入金」・売掛金（A社）が入る → 登録すると期日超過が 0 になり、「やること」も消える
  - 買掛金（補助科目なし）では支払条件を設定できない案内。法人のサンプルの売掛金・買掛金の一覧

## 未確認・今後

- 受取手形・支払手形、未収入金・未払金は対象にしていない
- 前期の明細を使った正確な経過日数（前期から繰り越した残りの発生日）は出していない

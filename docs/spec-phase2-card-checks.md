# クレジットカード明細の取り込みと仕訳のチェック（v0.28.0）

## クレジットカード明細の取り込み

- 入力メニューの「クレジットカード明細の取り込み」（`#/import/card`）。銀行明細の取り込みと同じ画面を `route.kind === 'card'` で切り替える
- カードの科目：流動負債の科目から選ぶ。既定は未払金（hint `accrued`、補助科目があればそれを優先）
  - カードが複数あるときは、未払金に補助科目（カード名）を作るとカードごとに残高を分けられる
- 列の推定（`detectCardColumns`）：見出しの言葉から利用日・利用先・利用金額を見つける
  - 金額は「利用金額」を優先し、支払総額・当月支払金額などより先に選ぶ（分割・リボでも利用時の金額で計上する）
  - 利用者・会員の列は摘要にしない
  - 見出しの無い形式は値から推定する（銀行と同じ）
- 向き：カード明細は利用がプラス・返品がマイナスなので、符号を反転して銀行と同じ扱いにする（`negate: true`）
  - 利用：借方 相手科目 ／ 貸方 未払金
  - 返品・取消：借方 未払金 ／ 貸方 相手科目
- 重複の判定・振り分けルール・税区分の初期値は銀行明細と同じ（`source: 'card_import'`）。登録後はカードの科目の元帳を開く
- 消し込み：引落し日に銀行明細を取り込み、相手科目を未払金（同じ補助科目）にする

## 仕訳のチェック

帳票の「仕訳のチェック」（`#/reports/checks`）。誤りと決めつけず、確かめる候補を出す（`js/journal-checks.js` の純粋関数）

| 項目 | 判定 | 見出しの件数 |
|---|---|---|
| 重複の可能性 | 同じ日付で、明細（貸借・科目・補助科目・金額）がまったく同じ仕訳の組。行の順序は問わない | 数える |
| 現金・預金の残高がマイナスになった日 | 科目の役割が現金・預金のもの（補助科目ごと）。同じ日の入出金をまとめ、その日の終わりの残高で判定（入力の順序によらない） | 数える |
| 残高が通常と逆の科目 | 試算表の期末残高（残高側の金額）がマイナスの科目・補助科目。評価勘定（減価償却累計額など）は normalSide が逆なので対象外 | 数える |
| 税区分の確認 | 消費税集計の「税区分のチェック」の警告の件数 | 数える |
| 仮払金・仮受金の残高 | hint `suspense_paid`・`suspense_received` の科目で期末残高が0でないもの | 参考 |
| 今日より後の日付の仕訳 | 端末の今日より後の日付。10件まで表示し、残りは件数と最後の日付 | 参考 |

- 見出しには誤りの可能性が高い項目の件数を出し、参考の件数は括弧で添える（予定を先に入力する使い方があるため）
- 科目は名前ではなく役割（role）・区分（group）・hint で判定する

## 未確認・未対応

- 確認に使ったのは、楽天カード形式を想定して作った見本の CSV だけ。実在のカード会社（楽天・三井住友・JCB・アメックスなど）の実ファイルでは未確認。合わないときは「列の割り当て」で手で直せる
- カードの締め日・引落し日を登録しての自動消し込みは作っていない

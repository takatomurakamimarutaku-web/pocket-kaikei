# 内訳書の e-Tax 用 CSV（v0.50.0）

勘定科目内訳明細書（`js/breakdown.js`）を、国税庁の標準フォーム（令和6年3月1日以後終了事業年度分）の CSV 形式で書き出す（`js/etax-csv.js`）。
様式ごとのファイルを ZIP（`js/zip.js`）にまとめて保存する。内訳書の画面の「e-Tax用に書き出す」から使う。

機能精査の E-5「e-Tax 用データの出力」のうち、公開された仕様で作れる部分。
申告書本体の e-Tax データ（xtx）は、仕様が大きく電子署名も要るため作らない（理由は 6章）。

## 1. 使い方

1. 内訳書の画面で「e-Tax用に書き出す」を押す
2. 書き出すファイル・切り詰めた欄・使えない文字を確かめて「書き出す」
3. ZIP を展開したフォルダを、e-Tax ソフトの「財務諸表等の組み込み」→「勘定科目内訳明細書（CSVファイル）」→「フォルダの場所」で指定する
4. 空欄（所在地・登録番号・利率・日付など）を e-Tax ソフトで記入する

## 2. 形式（国税庁で確認・2026-10-29）

- 出典
  - CSV形式で作成する場合の留意事項：https://www.e-tax.nta.go.jp/hojin/gimuka/csv_jyoho2.htm
  - 作成方法：https://www.e-tax.nta.go.jp/hojin/gimuka/csv_jyoho2/make_csv.pdf
  - 標準フォーム（様式ID・バージョン）：https://www.e-tax.nta.go.jp/hojin/gimuka/csv_jyoho2_meisai_20240325a.htm
  - レコードの内容及び留意事項（全体版）：https://www.e-tax.nta.go.jp/hojin/gimuka/csv_jyoho1/10/all2.pdf
  - 組み込みの手順（e-Tax ソフト）：https://www.e-tax.nta.go.jp/manual/manual21.pdf
- ファイル名は「様式ID_バージョン.csv」（例：HOI010_4.0.csv）
- 文字コードは Shift_JIS。行の区切りは CRLF（Excel で CSV 保存したときと同じ。留意事項に改行コードの指定は無い）
- 標準フォームのタイトル行は削除して保存する決まりなので、見出しの行は書かない
- 項目はカンマで区切る。空の項目も「,」だけを書き、最後の項目が空なら行末に「,」が付く
- 全角の項目
  - 半角の英数字・記号・カナは全角にする（NFKC で半角カナと濁点を1文字にしてから、英数字・記号を全角にする）
  - 項目内のカンマは全角「，」。改行は全角の空白にする（留意事項では「"」で囲めば改行できるが、内訳書では不要と判断した）
  - JIS第1・第2水準（JIS X 0208）に無い文字は使えない。Shift_JIS の2バイトの範囲（1〜8区・16〜84区）で判定し、無い文字は「？」にして書き出す前に知らせる
  - よく使う異体字（髙→高、﨑→崎など）は、留意事項の「異字体・旧字体は統一文字または新字体に変換」に沿って置き換える
- 金額は区切りなしの整数。負の数は先頭に「-」
- 文字数の上限を超えた全角の項目は切り詰め、書き出す前に知らせる（補助科目の名前を短くするか、組み込んだ後に直す）
- 元号の番号は明治1・大正2・昭和3・平成4・令和5。月・日は2桁（留意事項の例「4,31,04,01」）

| ②受取手形 | HOI020_4.0 | 2 | 振出人、金額 |
| ③売掛金（未収入金） | HOI030_4.0 | 3 | 科目、相手先、期末現在高 |
| ④仮払金（前渡金） | HOI040_4.0 | 4-1 | 科目、相手先、期末現在高 |
| ④貸付金及び受取利息 | HOI040_4.0 | 4-2 | 貸付先、期末現在高、期中の受取利息額 |
| ⑤棚卸資産 | HOI050_4.0 | 5 | 科目、品目、期末現在高 |
| ⑥有価証券 | HOI060_4.0 | 6 | 銘柄、時価及び帳簿価額 |
| ⑦固定資産（土地・建物） | HOI070_5.0 | 7 | 種類・構造（科目名）、物件の所在地（補助科目の名前）、期末現在高 |
| ⑧支払手形 | HOI080_4.0 | 8 | 支払先、金額 |
| ⑨買掛金（未払金・未払費用） | HOI090_5.0 | 9-1 | 科目、相手先、期末現在高 |
| ⑩仮受金（前受金・預り金） | HOI100_6.0 | 10-1 | 科目、相手先、期末現在高 |
| ⑪借入金及び支払利子 | HOI110_3.0 | 11 | 借入先、期末現在高、期中の支払利子額 |
| ⑫土地の売上高等 | HOI120_5.0 | 12 | 売上（仲介）年月、売上（仲介）先、売上金額（下段） |
| ⑬売上高等の事業所別 | HOI130_5.0 | 13 | 事業所の名称、売上高、期末棚卸高 |
| ⑭人件費 | HOI141_5.0 | 14-3 | 役員報酬手当・従業員給料手当・従業員賃金手当の総額と計 |
| ⑮地代家賃等 | HOI150_4.0 | 15-1 | 貸主の名称、支払賃借料、摘要（科目名） |
| ⑮権利金等の期中支払 | HOI150_4.0 | 15-2 | 支払先、支払年月日、支払金額、権利金等の内容（摘要） |
| ⑮工業所有権等の使用料 | HOI150_4.0 | 15-3 | 名称、支払先、支払金額、摘要 |
| ⑯雑益等・雑損失等 | HOI160_4.0 | 16-1・16-2 | 区分（科目名）、取引の内容、相手先、金額 |

- 項目の数は「レコードの内容及び留意事項」の項番の数と同じにした（テストで確認）
- 同じファイルに入る内訳書（④・⑮・⑯）は、内訳書の並び（雑益等は 16-1 を先）に書く
- 金額基準でまとめた「その他（N件）」の行は、画面のとおり明細行として書く
- ⑯は、まとめた行も雑益等・雑損失等の別を保つ（`summarize()` の `carry`）

### 合計行
- 合計行のある様式（①②③④-2⑤⑥⑧⑨-1⑪⑬）は、行区分「1」の行に、留意事項で決められた金額の項目だけを書く
- 留意事項では「合計行がある場合は合計行で改ページ、無い場合は1ページの明細の最大数ごとに改ページ」とある
  - 合計行を最後に1行だけ付けると、明細が1ページを超えたときの扱いが資料から読み取れない
  - そのため、明細が1ページの最大数未満のときだけ合計行を付け、超えるときは付けずに画面で知らせる（推測による安全側の判断）

## 4. 書き出さないもの

- ⑭役員給与等の内訳（14-2）：項番9〜15（役員給与計など）は確認できたが、項番1〜8（役職名・氏名など）の並びと値の形（コードか文字か）を国税庁の資料（PDF の文字）で確認できなかった。誤った並びで書くと読み込めないため、書き出さずに e-Tax ソフトでの入力を案内する
- ⑨-2未払配当金・⑨-3未払役員賞与、⑩-2源泉所得税預り金の内訳：帳簿で分けていない
- 帳簿に無い欄：所在地、登録番号・法人番号、法人・代表者との関係、利率、担保、振出日・支払期日、数量・単価、面積、区分（有価証券の売買・満期・その他、地代・家賃）など

## 5. ZIP

- 無圧縮（格納のみ）。ローカルヘッダ・中央ディレクトリ・終端レコードの最小構成（PKWARE APPNOTE）
- ファイル名は UTF-8 の印（汎用フラグの bit 11）を付ける（中身の名前は英数字だけ）
- CRC-32 は検査値（"123456789" → CBF43926）と Node の `zlib.crc32` でテストした。Python の zipfile・unzip でも読めることを確かめた

## 6. 申告書本体の e-Tax データ（xtx）を作らない理由

- 法人税申告書の e-Tax データは、帳票ごとの XML スキーマ（数百の帳票・版）に沿った XML を作り、電子署名を付けて送る
- 電子署名には利用者の電子証明書（マイナンバーカードなど）と、署名の処理が要る。端末内だけで動く PWA では安全に扱いにくい
- e-Tax ソフト・法人税の申告書作成ソフトに数字を書き写す（別表・決算書の画面）か、内訳書の CSV を組み込むほうが、誤りが少ない

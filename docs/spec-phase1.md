## 3. データ設計（IndexedDB）

DB 名 `pocket-kaikei`、`DB_VERSION = 1`。読み書きは Repository（`js/db.js`）だけが行う。

### 共通項目

全レコード（meta を除く）に `id`（`crypto.randomUUID()`）、`createdAt`・`updatedAt`（ISO 8601 文字列）。
削除時は本体を消して `tombstones` に `{ id, store, deletedAt }` を同じトランザクションで書く。

### ストア

| ストア | キー | インデックス | 内容 |
|---|---|---|---|
| `meta` | `key` | — | `settings`、`deviceId`、`currentPeriodId`、`lastBackupAt`、`seenVersion` |
| `accounts` | `id` | `code`（unique） | 勘定科目 |
| `subAccounts` | `id` | `accountId` | 補助科目 |
| `periods` | `id` | `startDate` | 会計期間と期首残高 |
| `journals` | `id` | `periodId`、`date` | 仕訳（明細 `lines` を内包） |
| `tombstones` | `id` | `store` | 削除履歴 |

### レコードの形

```js
// meta: settings
{ key: 'settings', value: {
  businessName: '村上商店',
  entityType: 'individual' | 'corporation',   // 初期設定後は変更不可
  taxStatus: 'taxable' | 'exempt',            // 後から変更可
  createdAt, updatedAt } }

// accounts
{ id, code: '112', name: '普通預金',
  group: 'current_assets',          // 区分（4章）
  role: null | 'cash' | 'owner_capital' | ...,  // 役割（特別な扱いをする科目だけ）
  normalSide: 'debit' | 'credit',   // 残高の側。評価勘定は区分と逆
  defaultTaxCategory: 'none',       // 仕訳入力時の税区分の初期値
  active: true, sortOrder: 112, createdAt, updatedAt }

// subAccounts
{ id, accountId, name: 'みずほ銀行', active: true, sortOrder, createdAt, updatedAt }

// periods
{ id, startDate: '2026-01-01', endDate: '2026-12-31',
  openingBalances: [ { accountId, subAccountId: null | id, amount } ],  // amount は normalSide 側の残高（整数）
  createdAt, updatedAt }

// journals
{ id, periodId, no: 12,            // 期間内の通し番号（削除しても詰めない）
  date: '2026-04-01',
  lines: [ { side: 'debit' | 'credit', accountId, subAccountId: null | id,
             amount: 1100, taxCategory: 'purchase_10', memo: '文具' } ],
  createdAt, updatedAt }
```

設計判断：
- 明細を仕訳レコードに内包する（別ストアにしない）。仕訳単位で原子的に保存・削除でき、同期時も仕訳1件が1単位になる
- 期首残高は `periods` に持たせる。第2弾の年度繰越で「前期の期末残高→次期の期首残高」を作るときに期間ごとに独立させるため
- 摘要は明細ごとに持つ（弥生の振替伝票と同じ）。仕訳帳では1行目の摘要を代表として表示
- 第1弾では会計期間は1つ（`currentPeriodId`）。ただしデータ構造は複数期間に対応

| `intangible_fixed_assets` | 無形固定資産 | BS 資産 | 借方 |

### 評価勘定

`normalSide` を区分の既定と逆にする（減価償却累計額・貸倒引当金・期末商品棚卸高）。
集計では区分の向きで符号を付けるので、決算書では自動的に「△」で表示され、区分の合計から差し引かれる。

### 役割（role）

名前を変えても判定が崩れないよう、特別な扱いをする科目だけに付ける。役割のある科目は削除・区分変更・無効化ができない。

| role | 科目（初期名） | 使い道 |
|---|---|---|
| `cash`, `deposit` | 現金、預金類 | ホームの現預金残高 |
| `owner_capital` | 元入金（個人） | 期首残高の自動計算 |
| `owner_drawings`, `owner_borrowings` | 事業主貸・事業主借（個人） | 個人 BS の表示 |
| `capital_stock` | 資本金（法人） | — |
| `retained_earnings` | 繰越利益剰余金（法人） | 当期純利益を加えて BS に表示 |
| `opening_inventory`, `closing_inventory` | 期首・期末商品棚卸高 | 売上原価の表示順 |

税区分の初期値（例）：売上高・雑収入→課税売上10%、仕入高・多くの経費・固定資産→課税仕入10%、
受取利息→非課税売上、保険料・支払利息・法定福利費・土地→非課税仕入、給料・租税公課・減価償却費・専従者給与・法人税等・資産負債の大半→対象外。
あくまで入力時の初期値で、仕訳ごとに変更できる。

### 科目の編集ルール

- 追加：コード（数字。重複不可）、名前、区分、残高側（区分の既定を初期値）、税区分の初期値
- 編集：名前・コード・税区分の初期値・並び順はいつでも変更可。区分・残高側は仕訳や期首残高で使われていなければ変更可
- 無効化：入力時の選択肢から外す（既存の仕訳・帳票には残る）。役割のある科目は不可
- 削除：自分で追加し、どこにも使っていない科目だけ可（tombstone を記録）
- 補助科目：科目ごとに追加・名前変更・無効化。使っていなければ削除可

## 5. 初期設定と会計期間

- 入力：事業者名（必須）、個人/法人、会計期間、課税/免税
- 個人：期間は 1/1〜12/31 固定。年を選ぶだけ（既定は今年）
- 法人：開始日を選ぶと終了日は「開始日の12か月後の前日」を自動入力。短くする変更は可（設立初年度など）、12か月超は不可
  - 検証：`startDate <= endDate`、`endDate <= 開始日+12か月−1日`
- 完了時に科目テンプレートを登録し、`settings`・`deviceId`・最初の `period` を作る
- 個人/法人は後から変えられない（科目と決算書の前提が変わるため）。変えたい場合はデータの初期化（バックアップを促す）
- 課税/免税は後から変更可。免税事業者でも税区分は記録する（課税事業者になったときの判定材料になるため）。消費税集計の画面に「免税事業者のため参考表示」と注記する

## 6. 期首残高

- 貸借対照表の科目（資産・負債・純資産・事業主貸/借）を一覧し、`normalSide` 側の残高を入力する
- 補助科目がある科目は補助ごとに入力（「補助なし」の行も可）。科目の期首残高＝補助の合計
- **個人**：元入金＝期首の資産合計−負債合計（事業主貸・事業主借は期首は0とし、入力欄を出さない）を自動計算し、手入力させない
- **法人**：借方合計・貸方合計・差額を表示し、**一致しないと保存できない**（Repository でも検証。復元ファイルも同じ条件で検証する）
  ※念のため、試算表・BS・ホームには一致していない場合の警告表示を残す

## 7. 仕訳入力（振替伝票）

- 1行に「借方（科目・補助・金額・税区分）」と「貸方（同）」、行ごとの摘要。行の追加・削除で複合仕訳
  - スマホ幅では1行を「借方ブロック／貸方ブロック」の縦積みにする
- 日付（既定は前回入力日。会計期間外は不可）
- 科目を選ぶと税区分に科目の初期値が入る（手で変更可）。科目の選択は、コード・名前・よみの部分一致で絞り込み
- 摘要の入力候補：過去の摘要を使用回数順に表示（ホップ手帖の `attachSuggest` を流用）。候補を選んだとき、その摘要を使った直近の仕訳と同じ科目が空欄なら補完する（【要確認】不要なら外す）
- 画面下に借方合計・貸方合計・**貸借差額**を常に表示。差額が0でなければ［保存］を押せない
- 金額は「1,000」「１０００」なども受け付け、整数の円に変換。小数・0以下・1兆円以上はエラー
- 保存の検証（純粋関数 `validateJournal`。Repository でも再検証）
  - 借方・貸方それぞれ1行以上、全行に科目と金額
  - 借方合計＝貸方合計
  - 科目が存在する（無効化された科目は新規入力不可。既存仕訳の編集では残してよい）、補助科目がその科目に属する
  - 日付が会計期間内
- 複製：既存の仕訳から日付以外をコピーして新規入力画面を開く（番号は新しく採番）
- 保存後：「続けて入力」（日付を残して空の伝票）と「仕訳帳へ」を選べる

## 8. 仕訳帳

- 月ごとに表示（前月・翌月の切替、「全期間」も可）。日付順→番号順
- 1仕訳を1カードにし、借方・貸方の行を並べる（No.、日付、科目／補助、金額、税区分の略号、摘要）
- 検索：摘要・科目名・補助科目名の部分一致、金額の一致（「1100」で 1,100 円の明細を含む仕訳）
- タップで編集。編集画面から削除（確認ダイアログ、トーストで「元に戻す」）。削除は tombstone を記録
- CSV 出力：表示中の範囲（10章）

## 9. 帳票（純粋関数で計算）

共通：金額は3桁区切り、マイナスは「△1,000」。0の科目は試算表・決算書で非表示にできる（既定は非表示、切替可）。

### 9.1 総勘定元帳
- 科目を選択（補助科目を選ぶと補助元帳）。期間（月範囲）指定
- 行：日付、No.、相手科目、摘要、借方、貸方、残高
- 先頭行に「前期繰越／前月繰越」＝期首残高＋指定期間より前の増減
- 相手科目：同じ仕訳の反対側の明細の科目が1種類ならその科目名（補助があれば併記）、2種類以上なら「諸口」
- 残高は科目の `normalSide` 側をプラスとする

### 9.2 残高試算表
- 列：繰越残高、借方、貸方、残高（＝繰越＋借方−貸方。貸方残の科目は符号を逆にする）
- 区分ごとの小計と、借方合計＝貸方合計の検算行。一致しなければ警告表示
- 繰越残高：BS 科目は期首残高＋期間開始前の増減、PL 科目は期首からの累計（月範囲を指定したときのみ）
- 補助科目の内訳を展開表示できる

### 9.3 損益計算書
**法人**：売上高 → 売上原価（期首棚卸＋仕入−期末棚卸）→ **売上総利益** → 販管費 → **営業利益** → 営業外収益・費用 → **経常利益** → 特別利益・損失 → **税引前当期純利益** → 法人税等 → **当期純利益**

**個人**（青色申告決算書（一般用）損益計算書の並び）：売上(収入)金額（雑収入を含む）→ 売上原価 → 差引金額 → 経費 → 差引金額 → 各種引当金・準備金等（繰戻額等・繰入額等）→ 専従者給与 → **青色申告特別控除前の所得金額**

青色申告特別控除額・所得金額の計算は第2弾（決算書の様式）で扱う。

### 9.4 貸借対照表（期末時点）
**法人**：資産の部（流動資産／固定資産（有形・無形・投資その他）／繰延資産）、負債の部（流動負債／固定負債）、純資産の部。
繰越利益剰余金には当期純利益を含めて表示し、その下に「うち当期純利益」を表示する。

**個人**：資産（流動資産／固定資産／事業主貸）、負債・資本（負債／事業主借／元入金／**青色申告特別控除前の所得金額**）。
負債は流動・固定に分けない（決算書の様式に合わせる）。

検証：**資産合計＝負債・純資産合計**（期首残高が一致し、仕訳が貸借一致していれば必ず成り立つ）。テストで確認し、崩れた場合は画面に警告。

### 9.5 消費税の税区分別集計（参考）
- 税込経理方式。明細の税区分ごとに税込金額を集計
  - 売上系（課税売上10%・8%・輸出・非課税売上）：貸方でプラス、借方でマイナス
  - 仕入系（課税仕入10%・8%・非課税仕入）：借方でプラス、貸方でマイナス
- 課税売上・課税仕入の行に、割り戻しの参考値を表示
  - 税抜金額＝税込金額×100/110（軽減は100/108）、1円未満切り捨て
  - 消費税等相当額＝税込金額−税抜金額
  - うち国税相当額＝税込金額×7.8/110（軽減は6.24/108）、1円未満切り捨て。地方消費税相当額＝消費税等相当額−国税相当額
  - 整数演算で計算する（例：`Math.trunc(x * 100 / 110)` は x が整数なので丸め誤差が出ない範囲で計算。テストで確認）
- 出典：国税庁 タックスアンサー No.6383「課税標準額に対する消費税額の計算」（割戻し計算：税込金額×100/110 に7.8%、軽減は100/108に6.24%）https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6383.htm 、No.6391「課税仕入れに係る消費税額の計算」https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6391.htm
- 画面に「申告書の計算ではありません（課税標準額の千円未満切捨て、インボイスの経過措置、簡易課税・2割特例などは第2弾）」と明記する

税区分の一覧：

| コード | 表示 | 略号 |
|---|---|---|
| `none` | 対象外 | — |
| `sales_10` | 課税売上10% | 売10 |
| `sales_8r` | 課税売上8%（軽減） | 売8軽 |
| `sales_export` | 輸出売上（免税） | 輸出 |
| `sales_exempt` | 非課税売上 | 非売 |
| `purchase_10` | 課税仕入10% | 仕10 |
| `purchase_8r` | 課税仕入8%（軽減） | 仕8軽 |
| `purchase_exempt` | 非課税仕入 | 非仕 |

第2弾でインボイスの経過措置（80%控除・50%控除）などの税区分を追加する。区分コードを足すだけで済むよう、集計は税区分の定義表（税率・売上/仕入・控除割合）で動かす。

## 10. バックアップ・CSV

### バックアップ（JSON）
```js
{ format: 'pocket-kaikei-backup', version: 1, exportedAt, appVersion, deviceId,
  counts: { accounts, subAccounts, periods, journals, tombstones },
  settings, currentPeriodId,
  accounts: [...], subAccounts: [...], periods: [...], journals: [...], tombstones: [...] }
```
- ファイル名：`pocket-kaikei-YYYYMMDD-HHMM.json`。iPhone では共有シート（`navigator.share` にファイル）→「ファイルに保存」、使えなければダウンロード
- 復元：全件を検証してから**置き換え**（全削除→登録を1トランザクション）。検証に失敗したら何も変えない
  - 検証：形式・バージョン、各レコードの必須項目、金額が整数、仕訳の貸借一致、参照先（科目・補助・期間）の存在
  - 復元前に「現在のデータは消えます」の確認と件数の表示
  - 「追加で取り込む（マージ）」は第1弾では作らない。会計データを部分的に混ぜると番号や残高が崩れるため、同期（第2弾以降）で UUID・updatedAt・tombstones を使って実装する
- 最終バックアップ日時を `meta.lastBackupAt` に記録。未バックアップの仕訳があり、前回から14日以上経っていたらホームに催促を表示

### CSV（UTF-8・BOM付き。Excel で文字化けしないように）
- 仕訳帳：`No.,日付,借方科目,借方補助,借方税区分,借方金額,貸方科目,貸方補助,貸方税区分,貸方金額,摘要`（振替伝票の行単位。複合仕訳は同じ No. で複数行）
- 残高試算表：`コード,勘定科目,区分,繰越残高,借方,貸方,残高`
- 金額は `-1000` 形式（△は使わない）。ダブルクォート・カンマ・改行を含む値はエスケープ

## 13. 作業計画とPR

main が空のため、最初に `README.md`・`CLAUDE.md`・`docs/` だけの初期コミットを main に入れる（アプリのファイルは無いので公開しても動くものは無い）。以降は作業ブランチ→PR→CI（GitHub Actions で `npm test` と PWA チェック）→ main。

当初は「PR1：土台と会計コア／PR2：画面」の2本に分ける予定だったが、確認待ちの間に両方を手元で仕上げたため、
1本の PR にまとめ、コミットを「会計コア」と「画面」に分けてレビューしやすくした。

PR は CI が通り、スクリーンショットを確認してから main にマージする。GitHub Pages の公開設定（Settings → Pages → main / root）はたかとさんの操作が必要。

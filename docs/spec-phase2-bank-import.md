# 第2弾（5）銀行明細CSVの取り込み 仕様

ネットバンキングからダウンロードした入出金明細のCSVを読み込み、1明細＝1仕訳（口座 ⇔ 相手科目の2行）としてまとめて登録する。
CSV は端末の中で読むだけで、外部へは送信しない。新しいストアは追加しない（DB_VERSION・BACKUP_VERSION は変えない）。

## 1. 入口
- 入力メニュー「銀行明細の取り込み」（`#/import/bank`）
- 出納帳の「銀行明細のCSVを取り込む」（その口座・補助科目を選んだ状態で開く）

## 2. 読み込み
| 項目 | 内容 |
|---|---|
| 文字コード | BOM付き・正しいUTF-8ならUTF-8、それ以外はShift_JIS（多くの銀行の形式） |
| 区切り | カンマ（1行目にタブが多ければタブ）。ダブルクォート・セル内の改行に対応 |
| 見出しの行 | 先頭15行から、日付と金額の言葉がそろう行を探す（口座番号などの前置きを飛ばす）。無ければ中身から推定 |
| 列 | 日付・摘要・摘要2・入金額・出金額・金額（符号つき1列）・残高。見出しの言葉で推定し、利用者が直せる |
| 日付 | 2026/4/1・2026-04-01・20260401・2026年4月1日・令和8年4月1日・R8.4.1（時刻つき可） |
| 金額 | カンマ・円・¥・＋−・全角を受け付け、整数の円にする（小数は「金額が読めません」） |
| 飛ばす行 | 日付が読めない行（合計・注記）、金額が0か空の行（繰越など） |
| 並び | 新しい順のCSVは古い順に並べ替える |
| 摘要 | 摘要と摘要2をつなぎ、NFKC で半角カナを全角にする（100文字まで） |

列の推定は、三井住友・三菱UFJ・楽天・ゆうちょ・住信SBIの見出しに似せた例でテストしている。ただし見出しは開発時の知識による推定で、各銀行の実際のファイルでは未確認（違っていても画面で列を選び直せる）。
同じ見出しの形式で利用者が直した割り当ては、端末内の meta `bankImport` に覚える。

## 3. 確認
- 残高の列があるとき、前の行の残高＋金額＝その行の残高 にならない行を知らせる（列の割り当て違いに気づくため）
- 会計期間外の明細は登録できない
- 登録済みの仕訳と同じ日付・口座（補助科目）・入出金の向き・金額の明細には「登録済みかも」と表示し、初期状態で外す（同じ内容が複数あるときは、登録済みの件数まで）
- 最後の残高を表示し、登録後に出納帳の残高と見比べてもらう

## 4. 相手科目
- 過去の仕訳のうち、現金・預金の科目を使った借方1行・貸方1行の仕訳の摘要から、相手科目・補助科目・税区分を覚える（新しい仕訳を優先）
- 摘要が同じ → 摘要がその言葉（3文字以上）を含む（長い方を優先）の順で候補にする
- 科目を選ぶと、同じ摘要で未定の明細にも同じ科目を入れる
- 税区分は科目の初期値（候補なら過去の仕訳の税区分）。明細ごとに変えられる
- 相手科目が未定の明細は登録しない

## 5. 登録
- 入金：口座 / 相手科目、出金：相手科目 / 口座。口座側の税区分は対象外。摘要は銀行の表記のまま
- 仕訳に `source: 'bank_import'` を付ける
- Repository の `saveJournals()` で1つのトランザクションにまとめ、各仕訳を再検証する。1件でも不正なら1件も保存しない（通し番号は続けて振る）
- 登録後はその口座の出納帳（全期間）を開く

## 6. 振り分けルール（v0.12.0）

「銀行明細の取り込み › 振り分けルール」（`#/import/bank/rules`）で、摘要に含まれる言葉ごとに相手科目・補助科目・税区分を登録できる。

- ルール：`{ id, keyword, direction: 'any'|'in'|'out', accountId, subAccountId, taxCategory }`
- 当てはめ（`matchRule`、純粋関数）：摘要が言葉を含み（ひらがな/カタカナ・全角/半角・大文字/小文字を区別しない）、入金・出金の向きが合うもののうち、言葉の長いもの。同じ長さなら先に登録したもの。科目が無効・削除済みのルールは使わない
- 優先順位：振り分けルール → 過去の仕訳の摘要（従来の自動学習）。明細には「ルール「言葉」」「過去の仕訳から」の印を付ける
- 保存：設定（meta の `settings.bankRules`）。`Repository.saveBankRules` が全件を検証してから保存する（現金・預金の科目は相手科目にできない）
- バックアップ：設定と一緒に書き出される。古いファイル（項目なし）はルールなしとして読む。`bankRules` が配列でなければ不正なファイルとして止める。項目の追加だけなので `BACKUP_VERSION` は上げない

## 7. 未対応（後で検討）

- 複合仕訳（源泉徴収された入金など）への分割。登録後に振替伝票で直す

# 部門別損益（v0.43.0）

機能精査の D-5「部門別損益」。たかとの指示「提案してくれたものは全部実装して」（2026-10-29）による。
弥生会計の「部門」、freee の「部門タグ」に当たる管理用の集計で、税法の判断は含まない（決算書・申告書の数字は変わらない）。

## 使い方

- その他 →「帳簿の設定」→「部門」（`#/departments`）
  - 部門の追加（名前は20文字以内、同じ名前は不可）・名前の変更・並び替え（↑↓）
  - 「使わない」：入力の選択肢から外す。付けてある仕訳はそのまま。帳票には、その期間に金額があれば出す
  - 「削除」：仕訳・定型仕訳のどれにも付いていない部門だけ（付いている部門は「使わない」にする）
- 仕訳に付ける
  - 振替伝票：損益の科目（売上・経費など）を選んだ側に「部門」の選択が出る。貸借対照表の科目には出さない
    - 科目を選ぶと、直前に使った部門を自動で入れる（部門なしにも戻せる）。摘要の候補を選ぶと、前回の仕訳の部門も写す
    - 使わないにした部門は、元から付いていた仕訳を直すときだけ選べる
  - かんたん入力：「部門」の欄（任意）。選んだ部門は損益の科目の行にだけ付ける
  - 定型仕訳：振替伝票と同じ。呼び出した仕訳にも部門が付く
  - 部門を付けなかった行は「共通（部門なし）」として集計する
- 帳票 →「決算書・分析」→「部門別損益」（`#/reports/departments`）
  - 月の範囲、共通の売上・経費の配賦（配賦しない／売上高の割合／均等）、0円の科目の表示を選ぶ。範囲と配賦は URL に残る
  - 列は部門（並び順）＋（配賦しないとき）共通＋合計。行は損益計算書と同じ区分・段階利益
  - 下に利益率の行：法人は売上総利益率・営業利益率、個人は売上総利益率（差引金額÷売上(収入)金額）・所得率（控除前の所得金額÷売上(収入)金額）。売上が0以下の列は「—」
  - CSV（列の見出しは部門名）・印刷
- 仕訳帳：カードに部門のタグ。検索で部門名も探す。CSV に「借方部門」「貸方部門」の列（部門を1つも登録していなければ列を増やさない）
- 弥生会計の形式の書き出し：借方部門・貸方部門の列に部門名（弥生会計の側に同じ名前の部門が必要）
- 訂正・削除の履歴：明細に［部門名］を出す

## 集計の仕組み（`js/departments.js`）

- `departmentIncome`：損益の科目の明細を、部門（`departmentId`）ごとに借方−貸方で集計し、列ごとに `statements.js` の `incomeStatement` を呼ぶ
  - 合計の列は、部門を付けない損益計算書と同じ（テストで確認）。すべての行で「部門の列の合計＝合計の列」
  - 貸借対照表の科目に付いた部門は集計しない（入力画面でも付けない）
  - 登録にない部門 id（通常は起きない）は共通に入れる
- 共通の配賦は科目ごとに行う
  - 売上高の割合：各部門の売上高の区分（`group: 'sales'`）の合計を重みにする（マイナスは0）。売上高のある部門が無ければ配らず、その旨を表示
  - 均等：表示している部門の数で割る
  - 円未満は最大剰余法（`allocateYen`）：割った余りの大きい順に1円ずつ足し、配った合計が必ず元の金額に一致する。金額×重みが大きくても狂わないよう BigInt で計算
- 部門は管理用の集計なので、決算書・申告書・消費税の計算には使わない

## データ

- 部門：`departments` ストア（`DB_VERSION` 7 で追加）。`{ id, name, active, sortOrder, createdAt, updatedAt }`
  - 削除は tombstones（store `departments`）に記録する
- 仕訳・定型仕訳の明細：`departmentId`（付けたときだけ持つ。部門を使わない人の仕訳の形は変えない）
- Repository：`listDepartments`・`departmentUsage`・`saveDepartment`・`reorderDepartments`・`deleteDepartment`。仕訳・定型仕訳の保存では部門の存在と「使わない」を再検証する
- バックアップ：`BACKUP_VERSION` 7。`departments` を追加（6 → 7 は空の配列で変換）。部門の検証、仕訳・定型仕訳の部門の存在も確かめる
- サンプルデータ（個人）：部門「デザイン」「店舗」。デザイン料の売上・外注工賃・値引きはデザイン、店頭売上・仕入は店舗、家賃などは共通

## テスト（`test/departments.test.js`）と動作確認

- 配賦：合計の一致（マイナス・大きな金額・重み0）
- 部門の検証・並び順・使っている部門
- 仕訳の検証（存在しない部門、使わない部門は元から付いていた明細だけ可）、定型仕訳
- 画面の行と明細の変換で部門を保つ、部門名で検索
- 部門別損益：配賦しない・売上高の割合・均等、範囲、使わない部門、法人の段階利益、合計が損益計算書と一致、CSV
- Repository：追加・名前の重複・並び替え・削除できない／できる・tombstone・バックアップの往復と旧形式・復元
- スキーマ移行（バージョン6 → 7）
- 仕訳帳の CSV・弥生会計の形式の部門の列、サンプルデータ
- Playwright（390×844、明暗）：`shots/departments/`。部門の追加（重複はエラー）、かんたん入力で部門を付けて保存（損益の行だけに付く）、振替伝票の部門の選択、仕訳帳のタグと検索、部門別損益（配賦しない・売上高の割合・均等、損益計算書との一致、範囲、読み込み直し後も残る）、使わないにすると選択肢から消える、部門が無いときの案内
